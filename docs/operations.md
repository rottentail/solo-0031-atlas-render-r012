# 运行与恢复

生产启动前构建 `go build -o atlas ./cmd/atlas`。通过ATLAS_STATE指定独立可写状态路径，通过ATLAS_ADDR指定受信环境的监听地址。状态目录应由运行进程拥有；临时写文件与最终文件位于同一个目录。

同一状态路径的第二个进程会因为独占文件锁拒绝启动。锁文件可长期存在，锁的有效性由操作系统进程锁决定。不要通过删除锁文件启动第二个写进程。

SIGTERM或中断信号会停止领取任务，取消执行中的计算，等待HTTP请求和执行循环结束。执行中的任务保留running，下一次启动会重新入队。SIGKILL恢复用 `python3 scripts/walkthrough.py --workflow recover-render` 演练；只会结束该脚本自己启动的实例。

备份时先正常停止实例，复制状态JSON；恢复时向空的独立状态路径复制，再启动。不要把运行中手工编辑过的JSON直接作为新事实。启动校验拒绝不支持版本、损坏摘要、孤立关联、非法文档、循环组件引用和快照中缺失的组件闭包。备份包含PNG字节、全部快照引用闭包以及所有组件修订，无需从外部服务恢复。

组件修订只增不改，停用不会删除任何修订。状态文件会持续积累每个已发布修订，容量按组件数量×修订数量规划。旧版本状态（无components字段）启动时会补空map，并在下一次成功事务时写回，因此回滚到旧二进制前应保留备份。停用组件不会阻止已有快照渲染，但会阻止新快照和新场景引用；需要恢复前向生产时先 `POST /v1/components/{id}/state` 置回active。

容量观察入口是GET /v1/status。它报告未压缩的持久结果PNG字节总量、场景/素材/组件/快照计数和各任务状态数量，不代表堆内存峰值。完整状态在事务中复制并编码，因此长期积累会增加提交成本。当前未提供任务或快照删除；部署应按预期数据量规划状态盘和实例周期。结果清理入口仅删除PNG字节。历史事件超过500条会截断，但sequence继续增加。

采用组件更新与普通场景编辑共享同一状态事务。客户端遇到409时应重新读取场景revision和组件最新修订后决定是否重试；网络中断不能盲目重复采用，先读取场景确认是否已经提交。采用历史记录在场景的componentAdoptions中，可用于审计。

故障时保留当前状态文件和服务日志，在副本上检查。500表示事务未能完成；客户端可先读取原请求目标确认状态。提交任务时使用稳定幂等键，不能因为连接中断盲目换键。409应结合当前场景revision、快照state或收据语义判断。410说明成功结果字节已清理，任务成功事实仍保留。

`deploy/atlas.service` 是Linux systemd配置示例，需按实际用户、二进制和状态路径调整。macOS可直接运行同一二进制。当前未验证容器部署、跨进程共享写入、跨机器文件系统锁或网络存储。
